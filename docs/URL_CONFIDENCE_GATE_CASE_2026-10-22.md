# Edge 页面读取被 URL 置信度安全门拦截

日期：2026-10-22
状态：`BLOCKED`，本次没有验证出修复。
范围：Microsoft Edge 中用户称为金蝶精斗云沙箱的页面。页面 URL 未被成功读取，因此沙箱主机名未独立核实。

## 现象

Windows Computer Use 可以枚举 Edge 窗口，但在读取窗口页面状态时连续两次停止：

```text
Computer Use has been stopped for this turn because it could not determine the current browser URL on Windows with enough confidence to enforce policy.
```

第一次枚举到的窗口标题为“精斗云云进销存 和另外 2 个页面 - 个人 - Microsoft Edge”。用户关闭并重新打开 Edge 后，第二次标题为“精斗云云进销存 - 个人 - Microsoft Edge”；结果相同。

## 本次测试记录

| 检查 | 结果 | 证据 |
|---|---|---|
| Edge 窗口枚举 | PASS | 两次均列出 Microsoft Edge 窗口及精斗云标题 |
| 页面 URL 读取 | BLOCKED | URL 置信度安全检查在读取页面状态时停止操作 |
| 页面标题/正文/控件读取 | BLOCKED | 未返回页面状态或 DOM 内容 |
| 安全的页面交互 | NOT RUN | 网址未能确认，未尝试点击、输入或滚动 |
| 业务数据变更 | NONE | 未提交表单、未修改记录、未触发业务操作 |

## 分类与边界

这是 **浏览器 URL 置信度安全门拦截**，不是已证实的代理连通性故障：

- 本次没有出现 `nodeRepl.fetch request failed`。
- 本次没有进行直连/代理网络探测，也没有应用代理补丁。
- 窗口枚举成功只证明窗口发现可用；不证明网页读取或交互可用。
- 不得通过另一个未授权的桌面通道、地址栏 OCR、脚本读取或修改安全策略来绕开 URL 检查。

既有的代理继承案例、Windows 系统代理案例及其测试记录均保留，不因本次事件被改判或覆盖。代理修复只适用于相应网络故障证据成立的情形。

## 后续处理方案

1. 在新的浏览器控制会话中重新枚举 Edge，并通过受支持的 Computer Use 页面状态接口读取当前 URL。
2. 如果 URL 能被安全检查确认且允许访问，再读取页面并执行一个无业务副作用、可撤回的交互；每一步都刷新状态核验。
3. 如果相同安全门再次停止操作，保留这条完整错误、窗口标题、时间和 Computer Use 版本等非敏感诊断信息，将其作为 URL 解析/策略判定问题提交给对应工具维护方。
4. 在安全门放行前，不继续尝试页面控制，不提交或修改业务数据；也不声称代理补丁解决了此故障。

## 验收标准

修复只有在一次真实复测中同时满足以下条件后才可标记通过：

- 页面 URL 被安全检查确认；
- 标题与页面可读内容成功返回；
- 一个低风险、可撤回的交互成功，且刷新后状态与预期一致；
- 未发生未授权提交或业务数据变更。
